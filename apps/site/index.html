AI agents hold real money, and a hijacked one will happily spend it. Other tools tell an agent what looks risky, then let it decide. Clearance takes that decision away: without signatures from independent verifiers, the pool refuses the swap and the wallet refuses the payment.

From request to enforcement

  1. The owner sets limits

    Size, price impact, tokens and payees sit in the agent's ENS records. Verifiers read them from the chain, so no server can loosen them.

  2. The agent asks

    It sends the exact swap or payment to the API, and pays for the check with x402 or an API key.

  3. Verifiers check separately

    Each one pulls its own data from the chain. Fixed rules decide. A model can explain or veto, and can never approve.

  4. A quorum signs

    Two of three sign one clearance, bound to the agent, pool, direction, amount, expiry and nonce. A refusal is simply no signature.

  5. Big trades get a human and a second look

    Over the owner's limit, the owner approves with World ID. A Chainlink CRE workflow then re-derives everything and writes its finding on chain.

  6. The chain enforces

    A Uniswap v4 hook reverts any swap without a valid clearance. The agent's smart account refuses other pools, direct transfers and uncleared payments.

What a hijacked agent runs into

Prompt injection changes what the agent says. It doesn't change what the contracts accept. Each of these runs as a real transaction in the test suite, and you can run them yourself.
